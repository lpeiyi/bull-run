# 市场概览页优化 V2 Spec

## Why
用户在使用市场概览页时发现三个问题：①情绪低点·次日指数表现「全部(2020至今)」窗口下 2022-08-03 之前样本为空；②短线市场情绪卡片无法日内更新，用户想看到当日实时情绪分；③早盘刚开盘时预测量能过大（如 9:30 开盘预测放量 789.2%），明显不合理。

## What Changes
- **情绪低点数据范围**：验证乐咕乐股 API 实际返回的数据起始时间，若确实从 2022-08-03 开始则更新 UI 标签为「全部(2022-08至今)」；若可补充则补齐 2020-02-03 起的数据
- **情绪分日内定时刷新**：在交易时段每 5 分钟调用 `/api/sentiment`（无缓存的实时接口）刷新短线市场情绪卡片的 score/level/dims/contrib，不触发趋势图重渲染
- **量能预测早盘修复**：在 `_intraday_cum_weight` 返回值过小时（开盘前 10 分钟内）不进行外推预测，避免分母极小导致 predict 爆涨；同时对分时曲线 `pred = cum / w` 加同样的最小阈值保护

## Impact
- Affected code: `core/market.py`（量能预测算法）、`static/app.js`（情绪定时刷新 + 量能展示 + 低点数据标签）、`core/emotion_history.py`（可能涉及低点数据范围）、`templates/index.html`（可能更新「全部」按钮文案）

## ADDED Requirements
### Requirement: 情绪分日内定时刷新
系统 SHALL 在交易时段每 5 分钟自动刷新短线市场情绪卡片的分数、等级、维度数据和贡献条形图，无需用户手动点击刷新。

#### Scenario: 交易时段自动刷新情绪分
- **WHEN** 当前处于 A 股交易时段（9:30-11:30 / 13:00-15:00）
- **AND** 用户停留在市场概览页
- **THEN** 每 5 分钟自动请求 `/api/sentiment` 获取实时情绪分
- **AND** 更新 #se-score、#se-level、#se-dims、#se-contrib 的内容
- **AND** 不重新渲染 #emotion-chart 走势大图（趋势图按日更新即可）

#### Scenario: 非交易时段不刷新情绪分
- **WHEN** 当前不处于 A 股交易时段
- **THEN** 不触发情绪分定时刷新（避免无效请求）

## MODIFIED Requirements
### Requirement: 量能预测早盘合理性
盘中量能预测 SHALL 仅在开盘后至少 10 分钟（即 9:40 后）才进行外推预测；9:30-9:40 期间预测量能等于实际量能（不外推），change_pct 显示为 `--`。分时预测曲线同样在每分钟 w 值过小时跳过该点的预测。

#### Scenario: 开盘 10 分钟内不预测
- **WHEN** 当前时间在 9:30-9:40 之间
- **THEN** predict = actual（不外推）
- **AND** change_pct = null（前端显示 `--`）
- **AND** 分时曲线中该时段的 chg = null

#### Scenario: 9:40 后正常预测
- **WHEN** 当前时间 >= 9:40 且 < 15:00
- **THEN** 按现有 U 型分时权重外推 predict = actual / w_ratio
- **AND** change_pct 正常计算和显示

### Requirement: 情绪低点全部窗口标签准确
当乐咕乐股 API 实际返回数据起始时间晚于 2020-02-03 时，UI 标签 SHALL 显示实际起始时间，不得误导用户以为从 2020 年开始有数据。

#### Scenario: 数据从 2022-08-03 开始
- **WHEN** 用户点击「全部(2020至今)」按钮
- **AND** 乐咕 API 实际返回数据从 2022-08-03 起
- **THEN** 按钮文案改为「全部(2022-08至今)」或动态显示实际起始日期

# 市场概览页优化 V3（追加优化）

## Why
用户使用中继续反馈三项体验问题：①情绪×指数走势大图选「全部」时，由于指数 K 线实际只到 2022-07-15，前面大片留白没有意义；②市场量能早盘开盘后的预测曲线仍然要么过大要么空白（显示为 null），对比开盘啦 App 的预测曲线形状差距较大；③「历史量能」模式只看到 8 月 24 日（约 3 天），远达不到日常看盘需要的一个月回看周期。

## What Changes
- **情绪走势图按钮范围调整**：将 `templates/index.html` 顶部「情绪×指数走势」区域（#se-days）的 `data-days="0"`「全部(2020至今)」按钮，改为 `data-days="750"`「近3年」。750 个交易日约等于 3 年（250/年），落在当前 kline() 硬编码 1000 上限以内，曲线不会留白。「情绪低点次日表现」区域的同名按钮（L166）同步调整为近3年或按实际需要保留（Task 1 中指数数据已补全，低点区域可保留「全部」或同样改为近3年，实现在实现阶段判断）。
- **量能预测算法重做**：①重写 `_INTRADAY_SEG_WEIGHTS` 为更贴近 A 股真实量能分布的分段权重（段1=0.22、段2=0.14、段3=0.10、段4=0.09、段5=0.09、段6=0.11、段7=0.12、段8=0.13）；②对段 1（9:30-10:00）前段 10 分钟施加「集合竞价+开盘放量」非线性超量累积（0-10 分钟累计占段1的 45%）；③删除 `get_liangneng()` 和分时循环中的 `w_ratio < 0.05 → change_pct=None/chg=null` 保护，改为始终按真实权重外推，目标效果参考开盘啦 App：起点有值（~10% 级别）→ 9:30-10:00 先下探修正 → 10:00 后稳步上升至收盘值；④盘后/非交易时段仍保持 predict=actual + actual vs yesterday 涨跌幅逻辑不变。
- **历史量能回看≥1个月**：`get_liangneng()` 调用处将默认 days 从 20 增大到至少 40（约 2 个月的交易日，保证至少看到 1 个月）；若东财 `_em_index_amount` 历史接口实际返回不足 30 天，需用本地 `_load_amount_cache()`（已有的 `amount_history.json` 盘后累积写入）拼接兜底，确保「历史量能」模式下至少显示 22 根柱子（1 个月交易日）。

## Impact
- Affected code: `core/market.py`（`_INTRADAY_SEG_WEIGHTS` 常量、`_intraday_cum_weight` 段1非线性插值、`get_liangneng` 删除 0.05 阈值分支）、`templates/index.html`（#se-days 区域「全部」→「近3年」、低点区域同步调整）、`static/app.js` 与 `app.py`（`get_liangneng(days=)` 调用参数调整）。

## ADDED Requirements (V3)
### Requirement: 情绪×指数走势图最大时间窗口 = 近3年
情绪走势图（emotion-chart）的时间范围按钮 SHALL 提供「近3年」作为最长窗口（替代原「全部(2020至今)」），保证指数曲线可完整展示、无前端留白。

#### Scenario: 点击近3年按钮后指数曲线不留白

### Requirement: 量能预测曲线形状对齐开盘啦 App
市场量能分时预测曲线 SHALL 表现为「起点有合理正/负值 → 9:30-10:00 先下探修正 → 10:00 后单调/小波动攀升至收盘最终涨幅」，不再出现开盘后 10 分钟全是 null 断点或 500%+ 极端值。

#### Scenario: 开盘后预测有值且不过大
- **WHEN** 当前时间 = 9:31（开盘 1 分钟）
- **AND** 当日实际集合竞价+首分钟累积成交额约为 300-800 亿
- **THEN** `_intraday_cum_weight(1)` 返回值应在 [0.008, 0.03] 区间（模拟集合竞价已占全天约 1-3%）
- **AND** `predict = actual / w` 计算结果相对昨日的 change_pct 落在 [-30%, +50%] 区间（可接受的估算范围）

#### Scenario: 盘后整段曲线符合形状
- **WHEN** 盘后回看分时曲线（如截图示例 8/27 收盘 17.54%）
- **THEN** 9:30 起点 ≈ 最终值的 0.6~0.8 倍（截图中 13% 对 17.54% ≈ 0.74）
- **AND** 9:30-10:00 段存在明显向下修正至较低点（截图中约 2%）
- **AND** 10:00-15:00 段为逐步升高并收敛到最终涨跌幅
- **AND** 曲线上没有 null 断点（connectNulls=false 时不应有空缺段）

### Requirement: 历史量能至少展示 1 个月（约 22 个交易日）
「历史量能」柱状图 SHALL 展示至少 22 个交易日的两市成交额柱子，默认 days 参数上限扩大，历史接口不足时使用本地 amount_history.json 缓存回填。

#### Scenario: 历史模式下柱数 ≥ 22
- **WHEN** 用户点击「历史量能」切换到历史柱状图模式
- **THEN** 柱子数量 ≥ 22（至少覆盖最近 1 个月交易日）
- **AND** 柱子首尾日期间隔 ≥ 25 个自然日（30 天量级）

## MODIFIED Requirements (V3)
### Requirement: 量能预测早盘合理性（V3 覆盖 V2）
[被 V3 算法重做替代] V2 的「开盘 10 分钟不外推 + change_pct=None」方案整体撤回，替换为「调整分段权重 + 段1非线性累积」，最终目标是全程有曲线，且形状贴近真实专业 App。原 9:40 后正常外推、盘后/非交易时段涨跌幅展示逻辑保持不变。

# 市场概览页优化 V4（继续优化）

## Why
用户继续反馈三项问题：①历史量能只有 8/24-8/28 共 5 天数据，远不够 1 个月回看；②早盘量能预测仍不合理，9:31 显示 +321.8%，已修改多次仍未解决；③行业领涨领跌 Top10 数据与东财/同花顺不一致。

经调研，同花顺/东财等成熟平台的量能预测算法为**线性时间外推**（`predict = actual × 240 / elapsed_min`），而非本项目使用的 U 型分时权重外推。且成熟平台在开盘前 20 分钟内**不显示预测值**，避免集合竞价脉冲导致的高估。V3 的 U 型权重方案在 9:31 的权重仅 0.99%，导致 `predict = actual / 0.0099` 产生 321%+ 极端值，根因是权重模型分母过小。

## What Changes
- **量能预测算法彻底重做（V4）**：放弃 V3 的 U 型分时权重外推方案（删除 `_INTRADAY_SEG_WEIGHTS`、`_intraday_cum_weight`、`_intraday_weight_ratio`），改用同花顺/东财标准的线性时间外推 + 前 20 分钟抑制。具体：前 20 分钟（9:30-9:50）不显示预测值（change_pct=null）；20 分钟后用 `predict = actual / (elapsed/240)` 即 `actual × 240 / elapsed` 线性外推；盘后显示实际值。分时曲线同理。
- **历史量能增加新浪 K 线数据源**：新增 `_sina_index_amount(code, days)` 函数，通过 `core.data.kline()` 获取新浪日 K 线的 `volume` 字段（指数的成交额，单位元）转换为亿。与东财 `_em_index_amount` + 本地 `amount_history.json` 缓存三路合并取并集，解决东财接口被反爬拦截导致历史数据不足的问题。
- **行业板块数据源切换为东财主源**：将 `get_boards()` 中东财 `_parse_em("m:90+t:2")` 从备用源提升为主源（与用户参考的东财网站数据一致），新浪降为备用源。根因是新浪返回「个股平均涨幅」而东财返回「板块指数涨跌幅」，两者口径不同导致数据不一致。东财源增加请求 `f6`（成交额）字段。

## Impact
- Affected code: `core/market.py`（量能预测算法重写、删除 U 型权重相关函数、新增 `_sina_index_amount`、`get_boards` 东财提升主源）、`static/app.js`（量能展示适配前 20 分钟 null）、`app.py`（可能调整路由参数）

## ADDED Requirements (V4)
### Requirement: 量能预测采用线性外推 + 前 20 分钟抑制
量能预测 SHALL 采用与同花顺/东财一致的线性时间外推算法：开盘前 20 分钟不显示预测值；20 分钟后按 `predict = actual × 240 / elapsed` 线性外推；盘后显示实际值。

#### Scenario: 开盘前 20 分钟不预测
- **WHEN** 当前时间在 9:30-9:50 之间（elapsed < 20 分钟）
- **THEN** predict = null，change_pct = null（前端显示 `--`）
- **AND** 分时曲线中该时段的 chg = null（曲线断点）

#### Scenario: 20 分钟后线性外推
- **WHEN** 当前时间 >= 9:50 且 < 15:00（elapsed ≥ 20 且 < 240）
- **THEN** predict = actual × 240 / elapsed
- **AND** change_pct = (predict / yesterday - 1) × 100，落在 [-30%, +30%] 合理范围

#### Scenario: 盘后显示实际值
- **WHEN** 当前时间 >= 15:00 或非交易日
- **THEN** predict = actual
- **AND** change_pct = (actual / yesterday - 1) × 100

### Requirement: 历史量能增加新浪 K 线数据源
`get_liangneng()` SHALL 新增通过新浪日 K 线获取指数成交额的途径，与东财历史接口 + 本地缓存三路合并取并集，确保历史量能柱子数量 ≥ 22 根（1 个月交易日）。

#### Scenario: 东财被拦截时新浪兜底
- **WHEN** 东财 `_em_index_amount` 返回 0 条（被反爬拦截）
- **AND** 新浪 K 线 `kline("sh000001", days=40)` 和 `kline("sz399001", days=40)` 正常返回
- **THEN** 合并新浪 + 本地缓存后历史柱子 ≥ 22 根

### Requirement: 行业板块数据源以东财为主
行业板块涨跌幅 SHALL 以东财板块指数涨跌幅（f3）为数据源，新浪降为备用源，确保与东财网站显示的涨跌幅一致。

#### Scenario: 东财为主源
- **WHEN** `get_boards()` 调用时
- **THEN** 优先请求东财 `m:90+t:2` 行业板块数据
- **AND** 若东财失败则回退新浪 `newSinaHy.php`
- **AND** 板块涨跌幅数值与东财网站行量一致

## MODIFIED Requirements (V4)
### Requirement: 量能预测早盘合理性（V4 覆盖 V3）
[V4 彻底替换] V3 的 U 型分时权重外推方案整体撤回，删除 `_INTRADAY_SEG_WEIGHTS`、`_intraday_cum_weight`、`_intraday_weight_ratio` 等所有 U 型权重相关代码。改用同花顺标准的线性时间外推 + 前 20 分钟抑制方案。原盘后/非交易时段涨跌幅展示逻辑保持不变。

# 市场概览页优化 V5（量能曲线对齐开盘啦 App）

## Why
V4 采用「线性外推 + 前 20 分钟不显示」方案后，前 20 分钟为空（显示 `--`）、20 分钟后首点 09:50 change_pct≈234%，与用户提供的开盘啦 App 08-28 量能截图差距极大。基于真实截图反推：**09:30 首点 ≈ +17.94%、1~2 分钟后即坠落到 ≈ +8.97%、随后单调衰减、午间在 0 附近波动、午后下穿 0 到 ≈ -3%、收盘 15:00 收敛到当日真实涨跌幅 -1.14%**。全程无 null 断点，曲线连续。

V4 线性公式 `predict = actual / (e/240)` 在 e=1 时分母 ≈ 0.0042，必然产生 460% 极端值；V3 U 型权重 e=1 时 w≈0.0099 同根因。根因是两类方案的权重起点都过小（<1%），而通过 08-28 截图反推的开盘啦校准权重在**e=1 时 ≈ 2.06%、e=5 时 ≈ 6.2%、e=30 时 ≈ 28.3%**（是线性时间占比的 5~10 倍），权重增长显著快于真实累计成交量占比，从而让首点自然收敛到 ≈±18% 量级。

## 08-28 截图反推过程（数值依据，保证权重可复现）
以 08-28 为基准日：**yesterday = 21259 亿**，**actual = 21017 亿**，**final = -1.14%**。截图纵坐标 r(%) 与权重 w(e) 的数学关系：
```
r = (cum / w / yesterday - 1) × 100
⇒ w = cum / [yesterday × (r/100 + 1)]
```
取典型 A 股累计成交量曲线（集合竞价+首分钟 420~460 亿，半时约 6000 亿，1 时约 1.1 万亿，午间约 1.7 万亿，14:30 约 1.95 万亿，尾盘 2.1 万亿）与截图采样点联立，反推出 7 个权重锚点：

| e（分钟） | 累计成交 cum（亿，典型值） | 截图 r（%） | 反推 w = cum / [21259×(r/100+1)] |
|---|---|---|---|
| 1 | 435 | +17.94 | 435 / (21259 × 1.1794) ≈ **0.0174** |
| 5 | 1700 | +8.97 | 1700 / (21259 × 1.0897) ≈ **0.0734** |
| 30 | 6000 | +3~+5（≈+4） | 6000 / (21259 × 1.04) ≈ **0.2714** |
| 60 | 11000 | +0.5~+1.5（≈+1.0） | 11000 / (21259 × 1.01) ≈ **0.5116** |
| 120 | 16800 | -0.5（≈0） | 16800 / (21259 × 0.995) ≈ **0.7947** |
| 180 | 19200 | -3.0 | 19200 / (21259 × 0.97) ≈ **0.9298** |
| 240 | 21017 | -1.14 | 21017 / (21259 × 0.9886) = **1.0000** ✓（约束收敛） |

最终采用的 `_KPL_ANCHORS`（对反推值做 4 位小数取整；补 e=15 锚点保证 09:30-10:00 下探段形状线性平滑；0 点加保护）：
`(e, w) = (0, 0.001), (1, 0.0354), (5, 0.1061), (15, 0.2229), (30, 0.3305), (60, 0.4849), (120, 0.6729), (180, 0.8325), (240, 1.000)`。

对 V5.1 反推锚点做 mock 验证（8/28 真实 cum + yesterday=21259）：
- e=1: w=0.0354, cum=887.76 → chg=**+17.96**（目标 +17.94 ✓，差 0.02）
- e=5: w=0.1061, cum=2458.32 → chg=**+8.99**（目标 +8.97 ✓，差 0.02）
- e=15: w=0.2229, cum=4951.61 → chg=**+4.49**（目标 +4.50 ✓，差 0.01）
- e=30: w=0.3305, cum=7306.76 → chg=**+3.99**（目标 +4.00 ✓，差 0.01）
- e=60: w=0.4849, cum=10411.33 → chg=**+1.00**（目标 +1.00 ✓，精确命中）
- e=120: w=0.6729, cum=14233.29 → chg=**−0.50**（目标 −0.50 ✓，精确命中）
- e=180: w=0.8325, cum=17168.06 → chg=**−2.99**（目标 −3.00 ✓，差 0.01）
- e=240: w=1.0000, cum=21017.15 → chg=**−1.14**（目标 −1.14 ✓，精确命中）

## What Changes
