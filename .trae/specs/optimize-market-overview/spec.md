## ADDED Requirements (Task 17: 细节修正与体验优化，2026-08-26)

### Requirement: 涨跌双色进度条分隔改为灰色斜向分割条（/ 形状，两侧留白）
原「留白间隙」的分隔方式视觉不美观，需要改为「斜向的灰色斜杠分割条（斜切角度 ~45°~60°，样式类似符号 /）」，并在分割条的两侧（与红绿段相接处）保留少量留白，形成：红段 - 留白 - 斜杠 - 留白 - 绿段的层次。
该需求替换 Task 11 中「留白间隙 / 灰色直条」两种方案，最终交付仅保留「斜杠 /」样式。

#### Scenario: 分隔结构
- **WHEN** 红色上涨段与绿色下跌段均存在且都大于 0
- **THEN** 红色段与绿色段之间插入 1 段「斜向的灰色斜杠分割条」（倾斜角度 ~45°~60°，视觉样式类似字符 /），分割条主体厚度约 2~4px，高度与进度条一致
- **AND** 斜杠分割条的两侧（与红绿段相接的左右两侧）各保留少量留白（合计约 1~2 像素的透明间隙），避免红 / 绿与灰色贴死
- **AND** 分割条必须是斜线条（非水平 / 垂直直条），可通过伪元素 + skew / linearGradient 135° stop / clip-path 三种方式之一实现，肉眼观感与「/」近似即可
- **AND** 分隔仅在红绿段均存在时出现，单边为零时不渲染斜杠分割条和留白，避免多余留白
- **AND** 分隔层不挤压红 / 绿两段的宽度百分比正确性（红 + 绿的宽度占比仍严格对应 上涨占比 / 下跌占比）

### Requirement: 指数走势对比曲线支持近 15/30/60 日切换
原指数对比卡只展示近 60 日，改为可切换近 15 / 30 / 60 个交易日，默认 60。

#### Scenario: 切换按钮
- **WHEN** 打开「指数走势对比」卡片
- **THEN** 卡片标题右侧或工具栏中出现切换按钮组（3 档：近15日 / 近30日 / 近60日）
- **AND** 默认高亮「近60日」，点击其他档位立即切换数据并重绘

#### Scenario: 后端支持
- **WHEN** 前端按不同档位请求
- **THEN** 后端 /api/index_compare 接受 query 参数 days ∈ {15, 30, 60}（缺省 60），并返回对应数量的对齐日期 + 归一化序列
- **AND** 缓存按 days 分档（15/30/60 分别独立 600s 缓存）

### Requirement: 市场情绪卡简化 + 修复迷你图为空与渐变未生效
用户反馈：1）右侧「情绪变化方向 + 6 因子徽章」与左侧仪表盘、六格信息重复，需要去掉；2）中部近15日情绪图显示为空、无任何数据、渐变颜色也未实现。

#### Scenario: 移除右侧重复区域
- **WHEN** 渲染 sent-card
- **THEN** .sent-right（含 #ov-sent-change 与 #ov-sent-factors）的 DOM 不再渲染或隐藏
- **AND** renderSentimentMini 不再依赖右侧容器，仅在中部 #ov-sent-big 渲染
- **AND** renderSentimentFactors 与 renderSentimentChange 可以保留函数定义，但不在 renderOverviewSentiment 中调用
- **AND** sent-card 内部布局改为「左仪表盘三列」→「左 仪表盘 + 六格 + tip；中 近15日情绪图」的两列布局（右列留空不会产生扭曲）

#### Scenario: 修复迷你图空数据
- **WHEN** /api/overview 返回的 sentiment.history_scores 长度 ≥1（当前截断约束为最多 15 点）
- **THEN** 中部近15日情绪图可以看到折线、数据点和坐标轴，不为空白
- **AND** 若 history_scores 确实为空，页面显示「暂无历史情绪数据」降级提示，不抛 JS 错误
- **AND** renderSentimentMini 里 yAxis 配置符合 ECharts value 轴规范（不得在 type=value 上同时设置 data 数组），避免 ECharts 静默失败

#### Scenario: 渐变实际可见
- **WHEN** 迷你图正常渲染
- **THEN** 图表绘图区背景的 splitArea/linearGradient 能肉眼看出：上方（值 60~100）橙红色系、越靠沸点越深；下方（值 0~40）冰蓝色系、越靠冰点越深；中间 40~60 过渡近透明

### Requirement: 行业领涨领跌 Top10 横条样式升级（参考附件）
参考目录根下附件 行业领涨领跌top10.png：左右严格分隔的双栏布局，领涨/领跌 Top10 使用横条进度条，信息密度与顺序需对齐参考图。

#### Scenario: 左右两栏带独立标题
- **WHEN** 打开「行业领涨领跌 Top10」卡
- **THEN** 卡片分为左右两栏，每栏有独立小标题：左侧「领涨 TOP10」（红色）、右侧「领跌 TOP10」（绿色）
- **AND** 两栏之间有一条竖向分隔线，保证视觉边界清晰

#### Scenario: 每行结构对齐参考图
- **WHEN** 渲染每一行
- **THEN** 领涨每行按「序号徽章 | 行业名称 | 涨幅值(右对齐) | 红条(自名称向右延伸)」布局
- **AND** 领跌每行按「绿条(自跌幅向左延伸) | 跌幅值(左对齐) | 行业名称 | 序号徽章」布局（与当前现有方向一致）
- **AND** 序号徽章 TOP1/2/3 用更醒目的三色（如金/银/铜或红黄渐变），第 4~10 名用普通深色徽章
- **AND** 名称与进度条之间不能出现换行错位，使用 flex + min-width 防止折断

#### Scenario: 归一化与空态
- **WHEN** 数据完整
- **THEN** 左右两侧最大进度条长度依然按 max(|maxUp|,|maxDown|) 统一归一化刻度，保证比例可比
- **AND** 无行业数据时显示「暂无行业板块数据」降级提示，不破坏布局

### Requirement: 综合黄金行情卡 — 修复历史折线 Y 轴与 Tooltip 数据口径
当前问题：近 30 日伦敦金迷你折线图的价格 Y 轴刻度不对，鼠标悬停金色线条时 Tooltip 显示的价格也不对（当前 history_xau = 黄金ETF 518880 收盘价，单位元/份 ≈ 4~6，直接标为伦敦金价格会误导）。

#### Scenario: Y 轴与 Tooltip 口径一致
- **WHEN** 渲染黄金历史折线
- **THEN** 若数据实际是黄金 ETF 518880 代理序列，则折线标题、Y 轴命名、Tooltip 文案统一改为「黄金ETF 518880 收盘价（代理）」，避免错误标注为伦敦金
- **AND** Y 轴默认 scale=true，保留足够小数精度，可在 tooltip.formatter 中再保留到 3~4 位小数，避免因数值小而显示粗整 0/5/10

#### Scenario: 数值一致性
- **WHEN** 鼠标悬停金色线条任一数据点
- **THEN** Tooltip 显示的日期 + 价格与 /api/gold 返回的 history_xau 数组中对应 close 值一致（最多保留 4 位小数）
- **AND** Y 轴刻度的数值范围与实际 close 序列 min/max 匹配（不再出现 0 / 1e6 这类离谱刻度）
