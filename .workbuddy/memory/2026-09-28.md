## ROADMAP 第 4 项：锁定依赖版本（已完成）

### 实施前必须理解的一点（本项的核心，最容易踩空）

`start.bat` 原本**每次启动都无条件**执行 `pip install -r requirements.txt`。
在 `>=` 时代这没问题（约束已满足 → pip 判定无需操作 → 秒退）；
**改成 `==` 之后语义反转**：本机版本只要与 pin 有偏差，每次启动都会尝试**联网**调整版本，
断网时 pip 失败 → `exit /b 1` → **起不来**，可靠性反而低于改造前。

所以「精确锁定」与「先探测、缺了才装」**必须成套落地**，不能只改 `requirements.txt`。

### 最终做法（与 ROADMAP 原建议不同）

原建议是 `pip freeze > requirements.lock.txt` 或改成 `~=` 兼容约束。**没走这条路**：

1. **只锁 4 项直接依赖**（`requests==2.34.2` / `flask==3.1.3` / `numpy==2.4.6` / `pandas==3.0.3`），
   不做全量 freeze —— 全量锁会把 `pywin32` 等平台专属包和全部间接依赖一并固化，
   换机器/换 Python 版本时反而更易装不上，且 60+ 行无法人工审阅
2. **`--missing` 刻意只判「包在不在」，不管版本对不对**。若把版本不符也算失败，
   本机版本高于 pin 时会反复触发联网降级安装 —— 正是上一条要避免的。
   版本一致性交给报告模式（人工执行）负责
3. `start.bat`：`check_deps.py --missing` 探测 → 齐备则 `goto :start` 直接启动（**不联网**）；
   缺失才走 pip install。注释改写成**英文**（cmd 按 GBK 解析，中文注释会变乱码并被当命令执行）

## 追加验证：启动链路端到端（提交后补做）

`tests/test_startup.py` 只对 `start.bat` 做**文本断言**、没有真跑它（真跑会启动 web 服务、
还可能自动弹出浏览器），所以另补了两个端到端验证：

1. **替身脚本真跑**：把 `start.bat` 里的 `"%PY%" app.py` 换成 `echo [FAKE] ...`、
   把 `pause` 换成 `rem`，另存为 `_tmp_start_test.bat`（`_tmp_*` 已被 gitignore），
   用 `cmd //c` 真跑。输出为：
   `[1/2] Checking dependencies...` → 直接 `[2/2] Starting dashboard` → `[FAKE]`，
   **没有** "Missing dependencies" 字样、也没有 pip 输出
   → 证实走的是 `goto :start` 分支，则 `:start` 标签存在、控制流未被改坏
2. **退出码直读**（用 Python `subprocess` 拿 `returncode`）：

   | 场景 | 退出码 | 对 start.bat 的含义 |
   |---|---|---|
   | 依赖齐备 `--missing` | 0 | 跳过安装，直接启动 |
   | 有包缺失 `--missing` | 1 | 触发安装分支 |
   | 有包缺失（报告模式） | 1 | 人工核查会报失败 |

### 踩到的坑：Git Bash 里 `cmd //c "带引号的完整路径 ..."` 不可靠

我先试了在 bash 里写
`cmd //c '"C:\...\python.exe" scripts\check_deps.py --missing >nul 2>&1 && echo A || echo B'`，
结果**输出了与事实相反的结论**（报"触发安装"，而实际应跳过）。

原因：`cmd` 对 `/c` 之后**以引号开头**的命令行会做引号剥离，完整路径被拆开
（路径含空格）→ 命令找不到 → `errorlevel 9009` → 走 `||` 分支。
**不是脚本的问题，是验证手段的问题。**

可靠做法（下次直接照用）：
1. 写临时 `_tmp_*.bat` 真跑（能真实验证分支）；
2. 用 Python `subprocess.run(...).returncode` 直读退出码。

**判断退出码别靠 bash 里拼 cmd 字符串。**

### 本次学到 / 踩到的

  设计阶段就预判到了（design §5.2），做法是**打全部可能挂载点**而不是逐个追。
  实测证明这比"搬一次改一次夹具"省事得多，且不会漏
