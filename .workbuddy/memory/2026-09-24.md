**spec**：`specs/fix-boards-source-selection/`（requirements / design / tasks 三件套）

### 根因（比初判严重，实为三个独立问题叠加）

1. **东财排序参数写错（主因）**：`_parse_em()` 用 `"fl": "f3"` 想按涨跌幅排序，
   但 `fl` 是「返回哪些字段」的参数、**不产生任何排序作用**；正确写法是 `fid=f3` + `po=1`。
   东财行业板块共 **496 个**（`total=496`），而代码只取 `pz=100`；排序失效后返回的是
   **按板块代码排序的前 100 个**而非涨幅最高的 100 个 → 高涨幅板块被整段截断。
   实测榜首：修正前「风电设备 +2.15%」→ 修正后「林业Ⅲ +5.83%」，**相差 2.7 倍** ——
   正对应老陆最初反馈的"涨幅偏低约一半"。
2. **双源校准从未生效**：新浪 49 个大类 vs 东财 496 个细分，**名称交集仅 6 个（重合率 12.2%）**，
   两源都先降序取前 5 后命中数仍为 0 → `hits >= 3` 永假 → 整段是死代码。
3. **同层级重复**：东财板块含Ⅰ/Ⅱ/Ⅲ 层级，修正排序后 Top10 会出现「林业Ⅲ +5.83%」
   与「林业Ⅱ +5.83%」成对重复，白占名额。

### 改动（`core/market.py`，+128 / −91 行）

- `_parse_em()`：`fl=f3` → `fid=f3`（附注释说明为何不能用 fl）
- `_compare_and_pick()` → `_pick_source()`：东财优先；东财为空或条数 <20 时回退新浪；双空返回 `[]`
- 新增 `_base_name()` / `_dedup_by_level()`：按「去掉末尾罗马数字后的基名」去重，保留靠前项
- `_parse_sina` / `_parse_em` 提到模块级（使请求参数可被测试断言，防止再次写错）
- 新增常量 `SINA_HY_URL` / `SINA_CON_URL` / `_MIN_SOURCE_ROWS=20` / `_LEVEL_SUFFIX`
- `get_boards()`：新浪改为**按需拉取**（正常路径网络请求 4→2 次），编排体约 70 行 → 12 行
