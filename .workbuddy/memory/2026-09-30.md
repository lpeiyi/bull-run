### 进展：老陆「继续吧」→ 参数全按建议值，design + tasks 已落盘（10:35~10:50）

同目录下 `design.md`、`tasks.md` 已完成，**待确认后进入执行（Phase 4）**。

**design 的核心结构：两条互相独立的闸门**
- **新鲜度**（TTL 分层）：行情窗口内 120s、窗口外 12h。窗口 = 交易日 09:15~11:30 + 13:00~15:00
  （**中午休市要排除**，否则午休期间会做约 45 次无谓拉取）
- **有效性**（`price > 0` 占比 ≥ 90%）：与新鲜度**不得合并**——09:00 的快照写入那一刻"新鲜"但"无效"；
  收盘快照 12 小时后仍"新鲜且有效"
- 两者用 `_directly_usable(cached, now)` 串起来；慢路径用 `_FETCH_LOCK` 做 single-flight + 双检，
  外加 `_MIN_RETRY_INTERVAL=60s` 抑制盘前空转

**关键设计细节（易踩坑，记牢）**
1. **判据必须看 `price` 不能看 `change_pct`**：盘前 `price=0` 占 63.5%，而 `change_pct` 仍残留上一交易日的值
   （23.4% 非零）→ 只看 `change_pct` 会把废快照误判为有效
2. **`_MIN_VALID_SAMPLE = 100` 豁免**：样本不足 100 时 `snapshot_is_valid` 直接返回 True。
   理由是非全市场样本算占比无统计意义；副作用是既有测试用 1 条桩数据的用例保持原语义
3. **v2 旧缓存要"当场判定"而非"一律放行"**：否则升级后那份 09:00 的废缓存会在回退路径复活。
   `_meta_valid_or_unknown`：v3 看标记，v1/v2 现算
4. **AC-2.3（跨时段失效）不需要专门代码**：昨晚 20:00 的 ts 到次日 10:00 是 14h > 120s，TTL 自然覆盖时段边界
5. **并发"分批"而非"一次发 60 页"**：一次全发会让断网场景发 180 个请求；
   分批（每批 = `_FETCH_WORKERS`）才能保住"连续失败早停"语义

**被否决的方案（附实测依据，别再提）**
- 拆成两个缓存文件 → 名单与行情来自**同一次拉取**，拆开不省请求
- 东财 `pz` / 新浪 `num` 放大 → 都硬限 100 条
- 腾讯 `real_quotes` → 全市场外推 69s
- TTL 直接 60s → 前端本就 60s 轮询，会变成"每 60s 一次全量"，120s 让轮询与更新解耦

**执行时两个必须注意的点**
1. **只允许改 2 个既有用例**：`test_consecutive_failures_abort_early`（断言了精确调用页集合/次数）与
   `test_fresh_complete_cache_used_without_fetch`（补 v3 版）。**其余 367 个一律不得动**（含 23 个路由契约）
2. **盘前场景无法真机复现**（验证时是盘中，拨不回 09:00）——用「时间打桩 + 真实形态桩数据」的离线用例替代，

  全市场拥挤度 / 大盘恐贪规则仓位 / 主线强度仪 / 变化追踪（趋势·异常·最近变化）
- **口径只给名字不给公式**：about 页只写"动量因子(Jegadeesh&Titman 1993) + Fama-French 三因子 +
  Carhart 四因子 + 技术面因子"，**不可复现**。区分度其实在"呈现与编排"，不在算法
- 恐贪分档与 bull-run 情绪分**同构**：极度恐惧 0~15 / 恐惧 15~30 / 中性 30~70 / 贪婪 70~85 / 极度贪婪 85~100
  （bull-run：冰点 0~25 / 偏冷 26~45 / 正常 46~65 / 偏热 66~80 / 过热 81~100）
- 附带一个**公益体检模块**（血压/血脂/尿蛋白），与 A 股无关 —— 抓首屏时混进来的那堆
  "档案归属/常用套餐/过敏史"就是它，不是 bug

**结论**：参考价值**中高**，但只能"取其信息架构，不可取其口径"。
最值得做的是 **板块主线强度仪**（bull-run 现在只有单一涨幅维度的 Top10，回答不了"是不是主线"，
而原料全在现有数据源里、是纯计算）；其次是 **情绪分历史分位/极值标注** 与 **变化追踪/复盘摘要**。
